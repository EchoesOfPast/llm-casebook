# E001 禁令清单式提示词（回顾）

| 项目 | 内容 |
|---|---|
| 情境 | [S001](../../scenarios/fiction/S001-reunion.md) |
| 方法 | [M001](../../methods/M001-rule-list.md) |
| 模型 | Gemini（基于 Flash） |
| 使用方式 | 网页对话 |
| 上下文 | 同一个长对话里多轮迭代 |
| 测试日期 | 2026-10-08 |
| 测试人 | 仓库作者 |

> 事后回顾，非规范实验：没有固定输入、每轮只有一次输出、提示词每轮都在变。这里只记录观察到的规律，不收录对话内容。

## 做法

在同一个对话里反复循环：给出“禁令清单 + 正反示范”的提示词 → 生成 → 作者指出问题 → 追加禁令。共十余轮。

## 观察

- **症状替代。**每禁掉一类问题，下一轮就出现另一类，大致顺序为 F01/F02 → F06 → F04/F05 → F10/F11 → F12 → F09 → F07/F15。
- **禁用词回流。**示范中写出的禁用细节，后来出现在了生成结果里。
- **示范自身违规（J03）。**模型写的“正确示范”违反了它自己列出的规则。
- **评判不稳定（J01）。**同一段文字的评价随用户语气翻转。
- **记忆篡改（J04）。**多轮之后，模型把自己的改写当作作者原文引用。

## 结论

无效。但这次测试没有回答“提示词能做到多好”，只说明了**长对话 + 禁令清单 + 模型自评**这种用法不行。

## 下一步想试

- 全新对话，不写禁用词清单，只用作者认可的文本做 Few-shot（[M002](../../methods/M002-author-anchor.md)）。
- 极短约束（字数、动作数）对比长规则。
- 同一提示词跑 3 次以上，换不同模型，盲评。
